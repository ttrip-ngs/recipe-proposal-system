# ADR 0006: 未知食材の辞書レビューに TypeSafe Jev を使う (判定は人が行う)

- Status: Accepted
- Date: 2026-09-27

## Context

アレルゲン検証は食材正規化辞書 (`guardrails/dictionaries/`) の完全一致に依存しており、辞書に無い
食材はアレルゲンタグが空になって食材リストの検査を素通りする (docs/guardrails.md §5)。未知食材は
週次で人がレビューして辞書に追加する運用だが、次の理由で追いついていなかった。

- 未知食材の warn ログ自体が未実装だった (memo/history/029 で実装)
- 表記揺れ・加工品・複数アレルゲンを含む調味料 (めんつゆ、ブリオッシュ等) の判断に知識が要り、
  1 件ずつ人が調べる負担が大きい
- 辞書の手作業管理で整合性不良が起きていた (味噌の大豆タグ漏れ, memo/history/028)

2026-09 に公開された TypeSafe の Jev は、テキストを生成せず、決まった選択肢からの選択 (Choice)・
Yes/No の確率 (Noul)・段階評価 (Score) だけを返す判定専用モデルで、1 回約 100ms、入力
$0.042/100 万トークン (出力無料)。公式ドキュメントは英語が最も得意で、日本語は自分のデータで
検証せよとしている。

既存辞書を正解に PoC した結果 (jev-1.13.0):

| 指標 | 日本語指示 | 英語指示 |
|---|---|---|
| 表記揺れ 169 件, 確信度 0.9 以上の正答 | 162/163 | 159/160 |
| 加工品 56 件, 全体の正答 | 48/56 | 42/56 |
| 辞書に無い食材 20 件のアレルゲン含有 (9 グループ) | 見逃し 0 / 過検出 3 | 見逃し 0 / 過検出 3 |

一方で「人参 -> 該当なし (確信度 0.98)」「焼きそば麺 -> そば」のように、確信度が高くても字面に
引きずられて誤る例がある。

## Decision

- Jev は **未知食材の週次レビューの補助** に限って使う。`scripts/review_unknown_ingredients.py` が
  `guard.unknown_ingredient` ログを集計し、未知食材ごとに canonical 候補・辞書語らしさ・
  アレルゲングループ含有の確率を付けた Markdown レポートを出す。アレルゲンの疑いがあるものを
  最優先の区分に振り分ける
- 辞書 (aliases.yaml / allergens.yaml) は自動更新しない。反映は必ず人が判断する
- 提案時のガードレール判定 (block / warn) には使わない。アレルゲン検証は決定論的コードのまま
  (CLAUDE.md 6.1)。Jev の判定で block を解除することも追加することもしない
- 指示文は日本語、モデルは版 ID (`jev-1.13.0`) で固定する。新版に上げるときは PoC
  (tmp の検証スクリプトと同等のもの) で閾値を確認し直す
- 外部に送るのは食材名のみ。家族のアレルギー・嫌いな食材などのプロファイルは送らない
- `typesafe-sdk` は dev 依存に入れる (本番イメージには含めない)。0.x で破壊的変更が続いている
  ため minor を固定する

## Consequences

### 正の影響

- 辞書の穴 (アレルゲンを含むのにタグが付かない食材) を、出現頻度とアレルゲン疑いの順に
  見られる。人は「調べる」から「確認する」に作業が変わる
- 本番の提案経路には何も足さないため、Jev の障害・誤判定・仕様変更が提案に影響しない

### 負の影響

- 新しい外部サービスと API キー (`TYPESAFE_API_KEY`) が増える
- データ保持をしない契約 (ZDR) はエンタープライズ限定。食材名のみを送るため許容する
- 過検出 (ピーナッツバター -> ナッツ、ココナッツミルク -> 果物 など) はレポート上のノイズになる

### 将来の検討

- 買い物辞書・価格対応表の追加候補にも同じ仕組みを広げる余地がある (必要になった時点で)
- 醤油 (小麦)・そばつゆ・カニカマなど、加工品の含有をどこまで決定論的に block するかは
  別途 ADR で決める (memo/history/028 残課題)
