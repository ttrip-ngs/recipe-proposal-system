# 031 未知食材の週次レビューに TypeSafe Jev を導入

2026-09-27

## 背景

表記揺れ・加工品の判定で辞書メンテが追いつかない問題に対し、2026-09-15 公開の判定専用モデル
TypeSafe Jev (テキストを生成せず Choice / Noul / Score を確率付きで返す) が使えるか検討した。
公式ドキュメント (docs.typesafe.ai) で確認した主な制約:

- 日本語は「扱えるが英語と同等ではない。自分のデータで試せ」
- 64k トークン / リクエスト、Choice の選択肢は最大 255
- エイリアス `jev-latest` は新版で中身が変わる。閾値を調整したら版 ID に固定する
- 既知の苦手: 字義どおりに読む、state 内の指示に引きずられる、数えられない
- 顧客データで学習しない。ZDR はエンタープライズ限定

## PoC

既存の aliases.yaml を正解に、使い捨てスクリプト (git 管理外) で約 540 呼出 x 2 (日本語 / 英語の
指示) を 15 秒で実行した。

| 指標 | 日本語指示 | 英語指示 |
|---|---|---|
| 表記揺れ 169 件 全体 | 165/169 | 165/169 |
| 同 確信度 0.9 以上 | 162/163 | 159/160 |
| 加工品 56 件 全体 | 48/56 | 42/56 |
| 同 確信度 0.9 以上 | 40/40 | 29/31 |
| 辞書に無い食材 20 件のアレルゲン含有 | 見逃し 0 / 過検出 3 | 見逃し 0 / 過検出 3 |
| 料理名の同一判定 16 組 | 15/16 | 15/16 |

- 日本語の指示の方が良い。英語では spaghetti -> 該当なし (確信度 0.96) など高確信の誤りが増えた
- 確信度が高くても誤る: 人参 -> 該当なし (0.98)。字面に引きずられる: 焼きそば麺 -> そば
- 辞書に無い食材の検出は Choice の「該当なし」より、別に聞く Noul (辞書語らしさ) の方が
  きれいに分かれた (辞書語の別表記・加工品 0.67 以上 / 無関係 0.45 以下)
- PoC の途中で味噌の大豆タグ漏れ (028) と、照合キーの不統一による素通り (030) を見つけた

## 対応

- `scripts/review_unknown_ingredients.py`: `guard.unknown_ingredient` ログ (029) を集計し、
  未知食材ごとに canonical 候補 (Choice)・辞書語らしさ (Noul)・全アレルゲングループの含有 (Noul)
  を 1 リクエストで聞き、Markdown レポートにする。振り分けはアレルゲン疑い > 別表記候補 >
  判断が割れた > 無関係。辞書は変更しない
- 閾値は PoC から: 辞書語らしさ 0.6 以上で別表記候補、0.4 未満で無関係、アレルゲン 0.5 以上で疑い
- `typesafe-sdk` を dev 依存に追加 (`>=0.7.2,<0.8`)、`.env.sample` に `TYPESAFE_API_KEY` を追記
- ADR 0006 で「レビュー補助に限り、ガードレール判定と辞書の自動更新には使わない」と決定

## 検証

- 集計・振り分け・レポートのテストを追加 (API は呼ばない)
- 実 API で 19 行 (16 種) のサンプルを実行し 0.9 秒。溶き卵・食パン・めんつゆ・ブリオッシュ
  などがアレルゲン疑いの区分に、ごぼう・塩などが無関係の区分に入った。タマゴは照合キー
  共通化 (030) で既知扱いになりレビュー対象から外れた

## 残課題

- 本番の Cloud Logging から実データでまだ回していない (本番デプロイ後に初回実施)
- 買い物辞書・価格対応表の候補付けへの展開は必要になった時点で行う
