# 032 通常は除去不要な食品 (醤油など) の可/不可をメンバーごとに選べるようにする

2026-09-27

## 背景

醤油は 大豆 の別表記で、大豆アレルギーでは常に除去、小麦アレルギーでは一切除去しない状態
だった。ガイドライン (食物アレルギーの診療の手引き2023 表16、生活管理指導表の「より厳しい
除去が必要なもの」欄) は、醤油・味噌・ごま油などを「多くの患者が摂取できる食品」とし、
除去は医師の指示で個別に決めるとしている。ユーザー判断で「アレルゲンを選んだら可/不可を
選択必須、未選択は除去」の案を採った (ADR 0007)。

## 対応

- 辞書: `allergens.yaml` (v4) に `usually_tolerated`。醤油・ごま油を独立 canonical にし、醤油は
  大豆と小麦の両方に属させた。大豆油・酢・麦茶・卵殻カルシウム・乳糖・乳清焼成カルシウムを追加
- 判定: `validators.blocked_allergens` に一本化し、事前フィルタもメンバー単位で同じ判定を使う
  (以前は家族全体の和集合)。摂取可の食品名 (ごま油) を伏せてから部分一致検査する
- 保存: `members.item_policies`。書き込みは `merge=[フィールド名]` に変更。`merge=True` は入れ子の
  map を再帰マージし、外したアレルギーの設定が残ることをエミュレータで確認した
- 画面: アレルゲンを選ぶと可/不可のラジオ (初期選択なし, required) が現れる。サーバ側で未選択を
  400 にする。除去不要候補はアレルゲンのチェックボックスから外した (大豆の下に「味噌」が
  出ていた問題も解消)。閲覧画面に「食べてよい」と「未設定 (除去扱い)」を表示
- LLM: `allergen_summary` を「大豆 (醤油・大豆油は使用可、味噌も除去)」の形にした
  (プロンプト YAML は変更なし)
- migration: `scripts/migrate_add_item_policies.py` (空の map を入れ、未選択の一覧を出す)

## 検証

- テスト 330 件合格 (エミュレータ起動で統合テスト含む)。追加: 未選択は除去、可の食品は通す、
  複数グループの食品、除去不要候補以外は可にできない、摂取可の食品名での誤検出なし、
  事前フィルタのメンバー単位判定、保存時の選択必須、item_policies の置き換え (統合)
- 認証と Firestore を差し替えた一時サーバで、編集画面の表示切り替え・required・保存・
  閲覧画面の表示をブラウザ (playwright-cli, 420px 幅) で確認
- migration をエミュレータで dry-run / apply / 再 dry-run (0 件) まで確認
- ゴールデン評価 (Fake) 10/11 (G101 は既存の失敗)

## 独立レビュー (design-reviewer) と対応

- (高) 摂取可の食品の表記を本文から伏せる方式は、「煮込みそば」の中の「みそ」(味噌) を消して
  そばを見逃していた。語の出現位置が摂取可の食品の表記の内側に収まるときだけ無視する方式に変更
- (中) LLM 向けの一覧で、醤油を大豆で可・小麦で未選択にしたメンバーに「使用可」と「除去」を
  同時に伝えていた。使用可の判定をガードレールと同じ allowed_items に揃えた
- (中) 小麦の「酢」は部分一致で米酢・黒酢なども止める。ADR と migration の手順に明記
- (低) migration: item_policies が null のメンバーで例外になる件、旧データ (allergens に味噌など)
  の警告を追加。保存層も null を未設定として読む
- (低) 不正値は家族の読み込みエラー (安全側) と data-model.md に明記。テストを追加

## 残課題

- **デプロイ直後**: 既存の小麦・卵・乳・ごまアレルギーのメンバーは未選択のため、醤油・味噌・
  酢・ごま油などを使う料理が提案されなくなる。migration の dry-run 一覧をもとにすぐ選ぶ
- 実 LLM (--live) のゴールデン評価は API クレジット補充後
- 魚のだし・魚醤、肉のエキスは未収録 (ADR 0007 将来の検討)
