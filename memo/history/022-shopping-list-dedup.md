# 022 買い物リストの重複行・水・調味料の扱いを改善

2026-09-26

## 背景

検証環境の買い物リスト (example-family 2026-W39) が 81 行あり、次の問題があった。

- 同じ物が複数行に出る: 砂糖 (大さじ / 小さじ / g の 3 行)、醤油 3 行、塩 3 行、にんにく 3 行など
- 名前が化ける・別物が混ざる: 醤油・豆腐・油揚げが「大豆」、牛乳が「乳」、ごま油と白ごまが「ごま」
- 表記揺れ: 生姜 / しょうが、酒 / 日本酒、オリーブ油 / オリーブオイル、かつおぶし / 削り節
- 水 3740ml が載っている
- 調味料が毎週「買うもの」に並ぶ

## 原因

集約キーにアレルゲン判定用辞書の canonical を使っていた。この辞書は含有アレルゲンで束ねる
ため (醤油 -> 大豆)、買い物の単位としては誤集約になる。加えて「単位混在は別行」ルールが
同一食材の多重行を生んでいた。

## 対応

- 買い物用辞書 `services/shopping_dictionary.yaml` を新設 (guardrails 辞書は変更しない)
  - `exclude`: 水・お湯など。リストに載せない
  - `pantry`: 常備品 (調味料・油・粉・だし類)。`pantry=true` で別欄・件数外
  - `items`: 生鮮の表記揺れ (生姜 -> しょうが 等)。部位違い (鶏もも / 鶏むね) は統合しない
  - 未登録の食材は NFKC + カタカナ->ひらがな で一致するものだけ束ねる (ニンジン / にんじん)
- 集約キーを食材 name の買い物用正規化に変更。1 食材 1 行で、単位ごとの数量を `amounts` に並記
  (大さじ・小さじ・カップ・cc・L は ml、kg は g に換算して合算)
- Firestore スキーマ変更: `total_quantity` / `unit` -> `amounts` / `pantry`。
  `scripts/migrate_shopping_items_amounts.py` を追加。読込側も旧形式を読めるので順序依存なし
- 手動追加アイテムは辞書に関わらず常に「買うもの」

## 仕様変更に伴うテストの書き換え

以下は条件緩和ではなく仕様変更による書き換え。

- `test_単位混在は別行` -> `test_単位混在は1行にまとめ_数量を単位ごとに並記する`
- `test_同_canonical_同_unit_は_合算される` (牛肉 + 牛切り落とし を合算) ->
  `test_別の日の同じ食材は_合算される`。部位・商品が違うものは別行にする仕様へ変更

## 検証結果

検証環境エミュレータで migration (dry-run -> apply -> 再 dry-run で 0 件) と再集約を実施。
81 行 -> 買うもの 32 品 + 常備品 21 品。水は除外、上記の重複はすべて 1 行に統合された。

## 追補: しょうゆ表記の追加 (2026-09-26)

- `shopping_dictionary.yaml` の醤油に `しょうゆ` を追加。LLM がひらがなで出力すると
  「醤油」と別の行になっていた
- 辞書変更時のテスト追加ルール (CLAUDE.md 6.2) に従い `tests/guardrails/test_shopping_dictionary.py` を追加
  (表記揺れの照合、薄口醤油との区別、醤油 + しょうゆ が 1 行に合算されること)
- `.pre-commit-config.yaml` の ruff-pre-commit を v0.7.0 から v0.15.11 に更新し、uv の ruff と揃えた。
  2 つのバージョンで `tests/guardrails/test_validators.py` の assert の整形結果が逆になり、
  `uv run ruff format` と pre-commit の両方を満たす状態が作れなかったため。
  このファイルの変更は整形のみで、テスト内容は変えていない

## 残課題

- LLM 出力の「鶏肉」(総称) と「鶏もも肉」は別行のまま。総称で出た場合の扱いは要観察
- 常備品の数量は ml 換算のため「砂糖 110ml + 46g」のような表記になる。在庫確認の目安用途
- 常備品リストは家庭ごとに違う。現状は YAML 編集で調整する
