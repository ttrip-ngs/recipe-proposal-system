# 030 食材名の照合キーを共通化し、表記違いのアレルゲン素通りを塞ぐ

2026-09-27

## 背景

Jev の検討で辞書まわりを調べたところ、照合の正規化が 4 か所で別実装になっていた。

| 箇所 | 旧正規化 |
|---|---|
| ガードレール辞書 (`NormalizerDictionary.normalize`) | `strip().lower()` のみ |
| 買い物辞書 (`shopping_dictionary.fold_key`) | NFKC + 小文字 + ひらがな化 |
| 価格対応表 (`cost.estimator._norm`) | NFKC + 括弧除去 + 空白除去 + 小文字 |
| 料理名の突合 (`weekly_planner._normalize_name`) | NFKC + 空白除去 |

最も緩いのが安全に関わるガードレールで、次がすべてアレルゲンタグ無しの未知食材になっていた。

```
タマゴ / ﾀﾏｺﾞ / ＥＧＧ / 卵（溶いておく） / 卵 (Mサイズ) / バター（有塩） / むきエビ / 鶏肉（もも）
```

## 対応

- `recipe_system/text_normalize.fold_key` を新設 (NFKC + 任意で括弧除去 + 空白除去 + 小文字 +
  カタカナのひらがな化)。4 か所すべてをこれに寄せた
- ガードレール: 照合キーで引き、見つからなければ括弧書きを除いて引き直す。
  重複登録の検出 (028) も照合キーで行うため「エビ」「えび」の衝突も起動時に止まる
- ガードレール: 辞書に無い食材 (タグ空) の名前にも、手順と同じアレルゲン語の部分一致検査を
  適用 (「溶き卵」「鶏ひき肉」のような複合語対策)。部分一致の語は畳まない (除外語「かに」で
  「カニ」まで外れるのを避けるため)。手順・食材名の文章は NFKC で全角英数を揃える
- 価格対応表 (version 2): ひらがな化で重複になった表記違い 39 件 (マグロ/まぐろ 等) を削除。
  単位表 `_MEASURE_UNITS` のキーも照合キーで持つ (「カップ」が引けなくなるのを修正)
- 買い物辞書は空白除去が加わった以外は同じ挙動

## 検証

- テスト 282 件合格 (追加: 照合キー、表記違いでのタグ付与、カナ違いの重複検出、
  辞書に無い複合語の block、二重報告しないこと、全角英字の手順、価格のカタカナ表記)
- ゴールデンセット評価 (Fake LLM) は 10/11。落ちる G101 (直近と重複: 肉じゃが) は main でも
  同じ結果で、Fake LLM が固定の献立を返すための既存の失敗

## 残課題

- 読みのカタカナと漢字 (ナットウ / 納豆、ギュウニュウ / 牛乳) は照合キーでは一致しない。
  辞書の別表記として追加するか、Jev による候補付けで拾う
- 「食パン」のように除外語 (パン) を含む複合語は、食材名の部分一致でも検出されない。
  辞書への別表記追加で対応する
- ココナッツミルク (ミルク) やピーナッツ (ナッツ) のように、辞書に無い食材名の部分一致は
  安全側の誤検出を起こしうる。実データで頻度を見る
